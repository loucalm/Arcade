# Effet CRT « bombé léger » — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** afficher toute l'image du jeu à travers un effet d'écran cathodique léger (variante G des maquettes).

**Architecture :** le canvas `PixelDisplay` (3 calques pixel) est rendu par une caméra dédiée dans une texture de la taille de l'écran ; un canvas Overlay affiche cette texture en plein écran avec le shader `Kenta/CrtDisplay` (fisheye, courbure, coins, lignes, adoucissement, lueur, vignette, gain). `FX/CrtScreen` fait la bascule ; `FX/CrtMath` porte la même géométrie en C# pour les tests.

**Tech Stack :** Unity 6000.3.23f1, Built-in RP, WebGL 2, shader CG ; tests EditMode (Unity Test Framework, sans asmdef).

**Spec :** [docs/superpowers/specs/2026-11-26-crt-design.md](../specs/2026-11-26-crt-design.md)

## Global Constraints
- Valeurs G : fisheye 0,06 · courbure 0,12 · coins 0,05 (fraction de la hauteur) · lignes 15 %, période 3 px de l'image · adoucissement 0,15 (prises à ±1,5 px) · lueur 0,12 · vignette 12 % · gain ×1,05 · pas de grille RGB.
- Une seule passe plein écran en plus ; pas de mipmaps régénérées ; aucune allocation par image (GC WebGL).
- Le jeu reste dessiné en pixels entiers ; seule l'image finale est déformée (exception à l'invariant 8, ADR-034).
- Ne pas toucher `Assets/Anatidae/**` ni les héros. Ne pas commiter `LiberationSans SDF - Fallback.asset`.
- Commits en français, à l'impératif, terminés par `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

2. Taille de la Game view ≠ 1920×1080, ou fenêtre redimensionnée : la texture suit l'écran, rien d'étiré ni de décalé → vérification Task 2, étape 6.
3. Effets de `ScreenGlitch` (copies plein écran, neige, miroir) et flash de `ScreenFx` : passent aussi par l'effet → vérification Task 2, étape 6 (menu Kenta > Tester le refrain 2).
4. F8 : l'image sans effet est identique à aujourd'hui (canvas revenu en Overlay) → vérification Task 2, étape 6.

### Task 1 : géométrie (`CrtMath`) et shader `Kenta/CrtDisplay`

**Files :**
- Create : `game/Assets/_Project/Scripts/FX/CrtMath.cs`
- Create : `game/Assets/_Project/Shaders/CrtDisplay.shader`
- Test : `game/Assets/_Project/Editor/Tests/CrtMathTests.cs`

**Interfaces :**
- Produces : `static class Kenta.FX.CrtMath` avec `Vector2 SourceUv(Vector2 screenUv, float fish, float curve)` et `float CornerMask(Vector2 screenUv, float fish, float curve, float corner, float aspect)` (aspect = largeur / hauteur ; 0 hors de l'image ou dans un coin, 1 dedans).
- Produces : shader `Kenta/CrtDisplay`, propriétés `_MainTex`, `_Fish`, `_Curve`, `_Corner`, `_Lines`, `_LinePeriod`, `_Soft`, `_Glow`, `_Vignette`, `_Gain` (valeurs G par défaut), `Blend Off`, compatible `RawImage` (UI).

- [ ] **Étape 1 : écrire les tests** `CrtMathTests` (fish 0,06, curve 0,12, corner 0,05, aspect 16/9) :
  - `Center_IsFixed` : `SourceUv((0.5,0.5))` = (0,5 ; 0,5) à 1e-5.
  - `FisheyeOnly_KeepsCorners` : avec curve 0, `SourceUv((0,0))` = (0,0) et `SourceUv((1,1))` = (1,1).
  - `Fisheye_MagnifiesCenter` : `SourceUv((0.6,0.5)).x` < 0,6.
  - `ScreenCorner_IsBlack` : `CornerMask((0.002,0.002))` = 0.
  - `ScreenCenter_IsVisible` : `CornerMask((0.5,0.5))` = 1.
  - `Hud_CornersStayVisible` : pour les points source (18/1920, 12/1080), (1 − 18/1920, 12/1080), (18/1920, 1 − 12/1080), (1 − 18/1920, 1 − 12/1080), trouver le point d'écran p tel que `SourceUv(p)` ≈ source (itération `p += source − SourceUv(p)`, 50 tours, écart < 1e-4), puis vérifier p dans [0,1]² et `CornerMask(p)` > 0,5.
- [ ] **Étape 2 : lancer les tests** (MCP `run_tests`, EditMode, filtre `CrtMathTests`) → échec de compilation (`CrtMath` absent).
- [ ] **Étape 3 : écrire `CrtMath`**, même calcul que les maquettes (`crt_gen2.py`) :
  ```
  c = uv*2 − 1
  k = 1 − fish + fish*(c.x² + c.y²)/2 ; c *= k                  // fisheye
  c = (c.x*(1 + (c.y*curve)²), c.y*(1 + (c.x*curve)²))          // courbure
  SourceUv = c*0,5 + 0,5
  CornerMask : 0 si |c.x| > 1 ou |c.y| > 1 ; sinon rx = corner/aspect,
    dx = max(|c.x| − (1 − rx), 0)/rx, dy = max(|c.y| − (1 − corner), 0)/corner,
    mask = saturate((1 − √(dx² + dy²))*25)
  ```
- [ ] **Étape 4 : relancer les tests** → 6/6 PASS. Si `Hud_CornersStayVisible` échoue, baisser `corner` (et la valeur par défaut du shader) jusqu'au passage, et le noter dans la spec.
- [ ] **Étape 5 : écrire le shader** (`Shaders/CrtDisplay.shader`, sur le modèle de `PixelDisplay.shader` : tags UI, stencil, `UNITY_UI_CLIP_RECT` inutile) ; fragment, dans cet ordre :
  1. `s` = `SourceUv` (même formule) ; `mask` = `CornerMask` ;
  2. `col = tex(s)*(1 − 2*_Soft) + (tex(s − dx) + tex(s + dx))*_Soft`, `dx = (1,5 * _MainTex_TexelSize.x, 0)` ;
  3. lignes : `col *= 1 − _Lines * sin²(π * s.y * _MainTex_TexelSize.w / _LinePeriod)` ;
  4. lueur : `col += _Glow * moyenne des 4 prises en s ± (6, 6) texels` ;
  5. vignette : `v = (16*s.x*s.y*(1 − s.x)*(1 − s.y))^0,25` ; `col *= (1 − _Vignette) + _Vignette*v` ;
  6. `col *= mask * _Gain` ; alpha 1.
- [ ] **Étape 6 : console Unity** (MCP `read_console`, erreurs) → 0 erreur de compilation du shader.
- [ ] **Étape 7 : commit** `Ajoute la géométrie et le shader de l'effet CRT`.
